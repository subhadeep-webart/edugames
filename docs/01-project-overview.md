# 01 — Project Overview

## What this is

**Trivia-SmackDown** (published under the *EduGames* banner) is a two-player,
fast-paced knowledge/trivia game that runs entirely in the browser. It is
designed to be played by **two people sitting at one computer**, not over a
network.

The player-facing site is `trivia-smackdown.com`; question data and helper
scripts are served from `edugames.com/cgi-bin/`.

## How a match is played

1. **Registration** — `index.html`. Both players enter a nickname, zip code
   and highest school grade. There is also a **Single Player Mode** button
   that skips the second player.
2. **Set selection** — the players pick a *Set*, which is a themed collection
   of *Rounds*.
3. **Play** — `GamePanel.html`. Players alternate having "the play". A round
   presents a challenge; the active player answers against a clock.
4. **Scoring** — points accrue per round and per set. Running totals are shown
   for the left (Blue) and right (Red) player.
5. **Game over** — `GameOver.html`.

### Two mice, one computer

The official rules recommend each player has their own physical mouse, and
optionally MouseMux so each player gets a separately coloured cursor. This is
a **hardware/etiquette** convention, not something the code enforces. Relevant
because the UI is built around two side-by-side player zones that must both
be reachable and readable at the same time.

Ground rules the UI is expected to support (from `Help/SimpleRules.html`):

- Keep hands off the mouse while the other player has the play.
- Once you have the play, start immediately — stalling to keep reading the
  challenge is treated as cheating.

## The three game types

From `Help/GameTypes.html`. Every round is one of three broad types, and the
letter suffix on the `Game*`/`Round*` classes maps back to these.

| Type | Name | How it works |
| --- | --- | --- |
| **B** | Bidding | Players bid on how many correct answers they can make. The point award is the **square** of the number of answers, so bidding high is high-risk/high-reward. |
| **D** | Data / Number | The answer is a number, a date, or a location on a map. |
| **I** | Incremental reveal | An image, music clip, sound byte or other evidence is revealed **slowly**; the sooner you answer, the more it is worth. |

`getHelpForThisTypeRound()` in `js/script.js` maps the many concrete round
letters onto these three help pages:

- `B, E, O, P, Q, U` → help type **B**
- `D, N, L` → help type **D**
- `I` → help type **I**

> ⚠️ That mapping function has a fall-through bug — see
> [10-known-issues.md](10-known-issues.md). It is **logic**, so leave it alone
> for this engagement, but be aware the help link can open the wrong page.

## Colour identity

Player identity is colour-coded throughout and this is load-bearing for the UI:

| Player | Index | Primary | Alt/secondary |
| --- | --- | --- | --- |
| Blue | `0` | `blue` | `SkyBlue` |
| Red | `1` | `red` | `Salmon` |

Defined in `js/Interface.js` as `playerColorArr` and `playerAltColorArr`, and
echoed in audio cues (`Audio/BluesTurn.wav`, `Audio/RedsTurn.wav`) and in
`js/BidButs.js` which paints `centerDisplay` with the active player's colour.

Any restyle must keep blue = player 0 (left) and red = player 1 (right).

## Audio is part of the experience

The game speaks and beeps constantly — turn announcements, countdowns, win
and loss stings. Files live in `Audio/` and are loaded at runtime by filename,
including **dynamically constructed** names such as:

```js
const txt = "Audio/Nbr" + seconds + ".wav";   // countdown numbers
buf += this.context.ui.bidButs.topBid + ".wav"; // bid announcements
```

This is why `Audio/` must stay in version control — see
[09-git-and-deployment.md](09-git-and-deployment.md).

## Technology summary

| Concern | Choice |
| --- | --- |
| Markup | Hand-written HTML, partly generated by CoffeeCup HTML Editor |
| Styling | Plain CSS — `js/TSDstyle.css` is the live one |
| Scripting | Vanilla ES6 classes, loaded via ~50 `<script>` tags |
| Modules | **None.** No `import`/`export`; everything is global scope |
| Build | **None.** Files are edited and uploaded as-is |
| Backend | Perl CGI on cPanel shared hosting |
| Data | Question banks compiled into large `js/Round*.js` files |
| Deployment | FTP upload |
